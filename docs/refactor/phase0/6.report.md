## 実施内容

- 一時的な処理状態だけを所有する`AuthLifecycleController`を追加し、AuthとUser Profileを別Repositoryのまま調停した。
- `initializing / signedOut / creatingAccount / sendingVerificationEmail / emailUnverified / reloadingIdentity / provisioningProfile / ready`と、再試行可能な失敗状態を定義した。
- Sign Up成功後に確認メールを送信し、送信成功時だけ送信済みメッセージを表示するよう変更した。
- メール送信失敗時は作成済みFirebaseアカウントを維持し、専用画面から再送できるようにした。
- 確認済み操作でFirebase Userを`reload()`し、再取得した`emailVerified`を基にProfile provisioningへ進むようにした。
- FirestoreのUID固定documentをtransactionでensureし、既存プロフィールの編集可能fieldや認可fieldを上書きしないようにした。
- Profile provisioning失敗時はAuth identityを維持し、再試行可能な中間状態にした。
- Firebase auth streamの変更をLifecycle Controllerへ集約し、旧CoordinatorからAuth Storeへの手動書き込みを除去した。
- sign-out後はAuth/User Storeをともに`null`へclearし、空accountIdの未認証`AppAuth`を廃止した。
- User refreshと同期は未確認状態では開始せず、Profile provisioning完了後の`ready`だけを自動同期の開始条件にした。
- Sign Up画面をLifecycle state駆動へ変更し、無条件の成功表示・画面遷移を除去した。
