## migration・account運用方針

- 旧global key `lastSync_wordStatus`はdatasetへ複製しない。複製すると未同期datasetを同期済みと誤認するため、初回scopedアクセス時に削除し、各datasetをsentinelからfull syncする。
- checkpointはsign-out時に削除せずaccount別に保持する。再sign-in時は同じaccountの値を再利用でき、別accountには異なるstorage keyが使われる。
- SharedPreferences保存精度はmillisecondsである。Firestore側のより細かいtimestampと境界が一致しても欠落しないよう`>=`で再取得し、重複適用を許容する。
- client clockが後退した場合はcheckpointも後退し得るが、取得範囲が広がる安全側の挙動になる。server cursorへの全面移行はPhase 2-6以降の戻り値再設計で扱えるよう`remoteCursor`をモデルに確保した。
