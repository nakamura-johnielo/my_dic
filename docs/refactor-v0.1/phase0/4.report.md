## 実施内容

- Esp-Jpn WordStatus、MyWord、MyWordStatus の同期処理から、`Result.runtimeType` と error 型を比較する誤判定を除去した。
- nullable な検索 API は `Result.success(null)` のみを不存在として扱い、`Result.failure` は `NotFoundError` を含め元の error のまま呼出し元へ返すよう統一した。
- list 取得の failure を確認してから成功値へアクセスする構造へ変更し、failure 後の `dataOrNull!` を防止した。
- 認証状態と同期 checkpoint の Repository failure を初回同期・未認証として扱わず、同期結果へ伝播するよう修正した。
- `UpdateMyWordStatusInteractor` が捨てていた保存結果を返し、保存 failure が `MyWordStatusCommand` の失敗イベントまで届くよう修正した。
- Esp-Jpn / Jpn-Esp status の既存 status 取得 failure を握りつぶさず返すよう修正した。
- ローカル更新後のリモート反映など、既存仕様上 best-effort の failure は警告ログに明示した。認証参照を省略してローカル処理を継続する経路も、空の failure/catch ではなく警告ログを残すようにした。

## API 契約の確認

- `getLocal...ById` / `getRemote...ById` は既存の `Result<T?>` を維持し、不存在を `success(null)` で表す。
- 同 API が返した `Failure` は create 経路へ変換しない。
- list API の空データは `success([])`、取得失敗は `Failure` として区別する。

## 追加テスト

`test/unit/features/sync/result_propagation_test.dart` に次を追加した。

- status 保存 failure が ViewModel command の失敗イベントへ届くこと
- ローカル検索の DatabaseError を伝播し、create しないこと

- 認証 Repository failure と checkpoint Repository failure が同期結果へ伝播すること
- failure 時に full-sync checkpoint を保存しないこと
